# Build guidelines:

- Each part should have its own component for better modularity and reusability.
- Use a consistent naming convention for components to make it easier to identify their purpose.
- Dont add many comments, only add comments where necessary to explain complex logic or decisions.
- Use a consistent coding style and formatting to improve readability.
- Follow attached designs when present
- API logic should reside in ../api/
- Fetch only when needed
- Follow how the previous designs are implemented, if there is a new design, follow the previous design patterns.
